# セーブ仕様と運用（Phase 8）

## 形式・署名

現在の形式は `rumor|v8|本体|署名`。Decimalを文字列にしたJSONをDEFLATE（LZ77を含む方式）で圧縮し、Base64URLへ変換する。ブラウザ標準のCompressionStream / DecompressionStreamを使用し、依存パッケージは追加していない。

署名対象はゲームID・版番号・本体の3項目（現在は `rumor|v8|本体`）。Web CryptoのHMAC-SHA256の先頭16バイトをBase64URLへ変換する。鍵は分割・XOR変換した定数から復元する。状態や鍵をwindowへ公開しない。ただしクライアントへ鍵を配布するため、完全な改ざん防止や、鍵を解析した利用者の再署名までは保証できない。

入力は最大1,000,000文字、ファイルと展開結果は最大1,000,000バイト。過大な展開は途中で停止する。別ゲーム、未対応版、不正なBase64URL、異常な署名長、展開・UTF-8・JSON・必須型・Decimalの破損は拒否する。

## 構造検査と整合性検査

共通仕様§6.2と§6.3を合わせ、構造を復元できないセーブは拒否し、構造が正常でも署名が不一致ならtaintedをtrueにする。読み込み失敗・キャンセル時は現在の進行を変更しない。

正しい署名でも、所持伝聞が累計を超える、購入した生産者が未解放、購入総額と所持量が累計を超える、現在の生産力・クリック数・進行時間による獲得上限を累計が超える、最終更新が未来、といった矛盾に改造印を付ける。計算誤差は倍率1.000001と0.001伝聞で許容する。

上限検査は今回の周回内で生産・クリック効率が減らない前提の保守的な検査で、過去の直接生産最大6倍・基礎クリック最大3倍を考慮する。転生でリセットする周回時間・クリック数と、生涯時間・クリック数を区別する。生涯累計、過去の最大所有数・最高周回累計・全生産者の同時最低所有数を保持し、転生前に達成した実績を検査する。研究の所有条件と支出、イベントとオフライン統計の整合も検査する。操作履歴の証明ではない。未知の状態フィールドは黙って捨てず拒否する。

改造印はヘッダーと統計へ表示し、通常保存や再エクスポートでも保持する。正規の別セーブを明示的に読み込む場合やハードリセット時は、その記録・新規状態へ置き換える。

## 旧形式の移行

v1 JSON→v2→v3→v4→v5→v6→v7→v8の順で移行する。署名付きv2・v3・v4・v5・v6・v7は元の版番号で署名を検証してから移行する。v1・v2の所持・累計・既存3生産者・クリック数・時間・乱数シード・設定・改造印を引き継ぎ、追加の7生産者・研究・イベント・オフライン統計を初期化する。v3からは旧累計・時間・クリック数を最初の周回と生涯記録の両方へコピーし、所有数などの到達記録を作る。語り草・転生回数・永続研究はゼロから開始する。旧記録で達成している実績を付与し、次の保存・エクスポートから署名付きv8になる。旧形式に存在しなかったオフライン統計は移行後の分から計測する。

既存localStorageとそのバックアップはローカル移行として扱い、整合性を検査する。署名のなかった当時の改変は証明できない。外部からテキスト・ファイルで読む旧形式は、署名による検証ができないため改造印を付ける。

本体が未対応の新しい版なら古いバックアップへの自動降格を行わず、元データを保護する。v4では生産者10種、通常研究・実績・永続研究のID、語り草の所持・累計・前回報酬・転生回数、周回と生涯の記録、無料の開始仲間数、イベントの待ち・表示・ブースト残り時間と生涯回収数、オフライン累計と直近報告を保存する。重複・未知のIDは構造異常として拒否する。

## 転生の保存と検査

伝説化はインポート・リセットと同じ排他処理を通す。確認後に新周回を保存し、成功した場合だけ画面の状態を置き換える。キャンセル・保存失敗では元の周回を保持する。確認中は操作・自動保存を止め、実行時には確認待ち時間を新周回へ加えない。

語り草は非負整数で、所持と累計の差が永続研究の支出に対応することを検査する。過去の獲得語り草と転生回数から必要な生涯獲得量の下限も検査する。無料の開始仲間5組は引き継ぎ研究と転生済みの記録を必要とし、現在の購入価格と支出から除外する。過去の所有数の支出下限にも無料分を保守的に考慮する。転生後のオフライン累計は生涯累計に対して検査する。

## 保存と復元

保存キーは設定定数の固定接頭辞を使い、フォルダ名やURLに依存しない。主セーブと直近3世代を保持する。同一文字列の再保存は世代を回さない。本体が破損した場合は新しい世代から復元を試し、復元不能なら自動上書きを停止する。設定から復元世代を選ぶこともできる。

30秒ごと・タブ離脱・手動操作でスナップショットを圧縮・署名して保存する。別タブの更新、容量不足、アクセス拒否は通知する。localStorageの複数キー更新はトランザクションではなく、複数タブの同時実行を完全に直列化する機構ではない。

終了時は非同期Web Cryptoを待てないため、通常250ms間隔とクリック・購入・設定変更時に署名済みスナップショットを準備し、beforeunload / pagehideで直近の準備済み記録を同期保存する。通常は短い差だが、署名待ちや急な終了では直前の操作が残らない可能性がある。確実に残すときは手動セーブの完了表示を確認する。

世代番号・処理番号で、古い非同期保存が新しい保存やインポート・リセットを上書きしないようにする。書き込みに失敗した置換データは終了時保存にも再利用しない。

## 操作

- テキスト書き出し・コピーと、`rumor_save_YYYYMMDD_HHmm.txt`へのファイル出力に対応。日時はブラウザのローカル時刻。
- テキスト・ファイルの読み込みは同じ検査を通し、確認後に保存できた場合だけ現在の状態を置き換える。読み込み・確認中のゲーム操作と自動保存は待機する。
- 確認はページ内ダイアログを使い、初期フォーカスとEscapeはキャンセル側。リセットは別々の2回の操作を要求する。
- リセットは新規状態を保存してから3世代のバックアップを削除する。削除だけ失敗した場合は進行リセット済み・削除未完了として通知する。他の保存キーには触れない。

## 検証

Vitestで圧縮・署名の往復、本体改変検出、正しい署名の不整合、過大入力、旧形式移行、破損拒否、バックアップ、保存失敗・競合、処理完了順、終了時保存、インポートとリセットの確認・キャンセルを検証する。

ブラウザでは旧形式の自動移行、テキストとファイルの入出力、コピー、破損拒否、改造印、正常な記録への復元、二重確認の最終キャンセルを確認した。Phase 4では伝説化のキャンセル・実行・再読み込み、永続研究の購入、通常の記録としての復元も確認した。公開URLとスマホ実機は未検証。

## Phase 5のミニゲーム記録

v5では取材券と回復時間・今回の消費伝聞・生涯のプレイ数と完了数と持ち帰り数・最高ポイント・挿絵・前回結果・ブースト残り時間を保存する。進行中は3個の共通乱数・現在の段階・選択・ポイント・残り時間・選択待ちかを保存する。v4からはミニゲーム状態を新設し、過去の最高周回累計が50,000以上なら初期券3枚を付与する。既存の進行と語り草は維持する。

開始・次の選択・持ち帰りはインポート・転生と同じ排他処理を通し、別状態を作って保存に成功した場合だけ採用する。開始前に費用・券・3段階分の乱数を確定する。保存失敗・連打で二重消費しない。保存済みの選択と乱数を使って段階終了を再現し、再読み込みでも成否を引き直さない。外部に保管した旧セーブへの巻き戻しは完全には防げない。

乱数の範囲と個数・段階・選択・時間・未知フィールドを構造検査し、券・成績・解放記録・ポイント・図鑑・今回の支出を整合性検査する。転生後は券・回復・図鑑・生涯成績を保持し、話・一時効果・今回の支出は初期化する。過去の全プレイ履歴を証明する検査ではない。
## Phase 6の階層・神話・試練・自動化

v6では10段の生成数（Decimal）、直近のオフライン生成数、神話数・編纂前までの語り草累計と伝説化回数、進行中とクリア済みの試練、自動化の個別ON/OFF・対象・優先順・保持額・語り草しきい値・次の処理までの経過を保存する。v5からは生成数・神話・試練をゼロ、自動化をOFFで追加し、既存の伝聞・語り草・図鑑・ミニゲーム進行を維持する。

神話編纂後も伝説化回数は生涯の記録として残す。編纂済みの回数を差し引いて現在の神話内の回数を検査し、語り草所持と永続研究の支出、現在の語り草累計、編纂前の語り草累計が必要とする生涯獲得量の下限を検査する。過去の無料仲間は過去の所有数の支出下限にも考慮する。

生成数は購入済みの段だけに生じること、現在の購入数を最初から持っていた場合の周回時間内の生成上限を超えないことを保守的に検査する。神話・試練・自動化の解放、試練中の購入・研究・クリック制限も検査する。順番の重複・不明な試練・負の生成数・不正なしきい値・未知フィールドは構造異常として拒否する。

神話編纂と試練の開始・中断・クリアは確認付きで、保存に成功した場合だけ新しい周回を採用する。自動伝説化は明示的にONにした場合だけ確認なしで実行し、通常の排他・保存処理を通す。保存に失敗したら周回を保持して自動伝説化をOFFにし、連続再試行しない。オフライン計算は自動購入・研究を反映し、周回リセットを行わない。設定変更も通常の署名済みスナップショットと自動保存の対象になる。

検査は完全な履歴証明ではない。アーカイブやオフライン報告は保存された到達記録に基づく。外部に保管した古いセーブへの巻き戻しや、鍵を解析した利用者による改変を完全には防げない。
## Phase 7の設定と復帰

保存v7は配色・演出・効果音・音量・自動保存間隔を追加する。v6の進行は変えず、夜・演出ON・音OFF・音量25%・30秒保存を初期値として移行する。設定は伝説化・神話・試練後も保持する。不明なキー、範囲外の音量、未定義の間隔は拒否する。

8時間の復帰は約8msの処理予算ごとにブラウザへ制御を返す。自動化は従来と同じ1秒境界、生成は同じ50ms漸化式で計算する。復帰中の操作を止め、インポート候補は完了・保存後にだけ採用する。途中で終了した場合は最後の完成済みスナップショットを保存し、未完了の報酬を確定しない。

## Phase 8の夜便・年代記

保存v8は夜便の解放、配達券と回復、今回の支出、生涯の開始・完了・成功回数、直近の正解数、収集順つき絵葉書、問題と回答・配達時間、年代記の読了印を追加する。v7からは未開始の状態を追加し、既存の経済・設定は変更しない。

開始と回答、エピローグの読了は保存できた場合だけ採用する。乱数は開始時に3問すべてを確定し、再読込で変えない。読了は4条件を満たした記録に限る。配列の長さ、宛先・文章の範囲、回答数と段階、配達時間、未知キー、券・回復の範囲、絵葉書IDの重複を構造検査し、解放条件・回数と収集数・収集順・支出を整合性検査する。正常な署名があっても矛盾には改造印を付ける。

伝説化・神話・試練で現在の便を取り消し、今回の支出をゼロへ戻す。券・回復途中・生涯成績・絵葉書・読了印は保持する。ハードリセットはこれらも初期化する。外部の古い記録への巻き戻しや再署名を完全には防げない制約は従来と同じ。
