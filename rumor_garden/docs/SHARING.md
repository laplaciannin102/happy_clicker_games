# クレジットと共有

全画面の下部と共有カードに「制作：laplaciannin102」を表示する。「制作者」タブには、本人指定のGitHubプロフィールへのリンク、ゲームに沿った紹介文とクレジットを掲載する。設計・プログラム・文章はlaplaciannin102とCodex（OpenAI）、画像はOpenAIの画像生成機能、効果音はWeb Audio、巨大数計算はbreak_eternity.js（MIT License）と記載する。

## 共有内容

メインのSNS共有で、開いた時点の所持伝聞と毎秒生産を文章へ固定する。PNGの記録カードには伝説・神話の数と制作名も含む。Canvasで直接描いた1200×630画像であり、実画面のスクリーンショットではない。追加の画像生成、画面取得権限、外部レンダラー、依存パッケージは使用しない。

- 文章をコピー：SNSなどへ貼り付けられる。クリップボードを利用できない場合は文章を選択して手動コピーする。
- 記録カードを保存：rumor_record.pngを端末へ保存する。Xなどの投稿画面で添付できる。
- 共有先を選ぶ：ブラウザ標準の共有機能を使う。画像を渡せる場合はPNGも含み、対応しない場合は文章と公開URLを渡す。ブラウザが共有機能を持たない場合はこのボタンを表示しない。
- Xでツイート：文章と公開URLをクエリーに入れたXの投稿画面へ移る。文章はX側で確認・編集し、利用者が投稿する。画像ファイルをURLのパラメーターで自動添付せず、保存したPNGを利用者が添付する。

公開URLは現在のディレクトリから作り、フォルダ名はハードコードしない。URLのクエリー・フラグメント、ローカル／プライベートIP、認証情報付きURLは共有対象外。セーブ文字列、鍵、乱数シードは含めない。改造印は文章と画像にも付ける。画面を開いてから閉じるまで、文章と画像の数字は同じ記録を保つ。

## 実装と制約

共有用の文章・リンクは純粋関数で作る。画像は共有画面を開いた時に端末内で生成し、送信ボタンのクリック前に用意する。閉じると画像のObject URLを解放し、生成途中の古い結果も採用しない。画像生成に失敗しても文章コピーとXリンクは使える。

Web Shareはユーザーのクリックと対応環境が必要で、ファイル共有可否はcanShareで確認する。標準仕様は[W3C Web Share API](https://www.w3.org/TR/web-share/)を参照。画像付き共有の可否・共有先・投稿画面はOSとブラウザに依存する。アカウントへのログインや実投稿を自動実行する機能はない。
