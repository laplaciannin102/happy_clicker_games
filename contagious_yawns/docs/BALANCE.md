> シミュレーターは `scripts/simulate.ts`。`npm run simulate` で能動・ゆったりの2つのボットを回す
> （長さは `SIM_HOURS` で変えられる。既定 6 時間。16 時間ぶんで実時間 約4分半。1本あたり実時間 12 分で打ち切る）。
> 初回おやすみまでの目標は `tests/pacing.test.ts` でふだんのテストにも入れている。

## ボットの動き

| | 能動プレイ | ゆったりプレイ |
|---|---|---|
| クリック | 毎秒 5 回 | 毎秒 1 回 |
| 流れ星 | 出たらすぐ拾う | 拾わない（画面を見ていない扱い） |
| アップグレード | 買えるものはすぐ買う | 同左 |

- 人が遊ぶと、買い物の迷いや画面を見ていない時間があるので、実際はこれより遅くなるはず。

## 調整の記録

### 2026-10-28：夢のかけらの式（Phase 4）

| 案 | 式 | 結果（能動・6時間） |
|---|---|---|
| 当初案（DESIGN v0） | floor(10 × (累計/1億)^0.5) | 85分で夢ツリー全部。6時間でかけら 1.2×10¹⁶。終盤は 6秒の周回でかけらが倍に |
| 指数 1/3 ＋ 条件 2億 | floor(10 × (累計/2億)^(1/3)) | 105分でツリー全部。かけら 4.7×10⁸ |
| 指数 1/4 | floor(10 × (累計/1.5億)^(1/4)) | 111分でツリー全部。0.1分の周回が続く |
| **採用：対数の2乗** | floor(10 × (1 + log10(累計/1.5億))²) | ツリーは6時間で 23/24。倍々の暴走は止まった |

- 原因：大きな倍率があると、安い生産者から高い生産者へ一気に「はしご」を登れるので、
  おやすみ直後の30秒で毎秒の生産が10万倍に伸びる。このため、累計の累乗でかけらを配ると、
  「かけら1個 +1%」との組み合わせで、かけらが時間に対して倍々に増え続けた。
- 夢ツリーの値段も、最初の案（全部で 470）から段ごとに大きく上げた（全部で 9,403）。

### 2026-10-28：受動ボーナスを √ に・眠気の連鎖（Phase 6a）

- かけらの受動ボーナスを「1個 +1%」から「√累計 × 10%」に。眠りの達人は「1個 +1%」から「係数 +10%」に。
- 眠気の連鎖（夢ツリー・100 かけら、`CHAIN.rate` = 0.02）を追加。

### 2026-10-28：冬眠・ぬくもり・季節（Phase 6b）

- 冬眠は夢ツリーを全部埋めたら。ぬくもりの水準 = floor(√(累計の夢のかけら / 1000))、全生産 +25%/個、ショップで倍率とノードの持ち越し。季節は 春→夏→秋→冬。
- **冬眠の空回りを直した**：最初は「冬眠するたびに水準ぶんのぬくもり」をもらえる形だったが、1回目の冬眠（162分）のあと
  約30秒ごとに冬眠を繰り返せた（6時間で200回以上）。ショップの倍率で夢ツリーを数十秒で埋め直せるため。
  → もらえるのは **水準がこれまでの最高を超えたぶんだけ** にした。

| マイルストーン（16時間） | 能動 | ゆったり | 目標 |

| 初回おやすみ | 31分 | 60分 | 30〜60分 ✅ |
| 夢ツリー全部 | 2.7時間 | 8.2時間 | — |
| 冬眠 | 2.7h(+3) → 5.7h(+1) → 6.9h(+1) → 9.9h(+1) → 13.8h(+2) | 8.2h(+3) → 12.5h(+1) → 13.8h(+1) | 初回 数時間〜1日 ✅ |
| 16時間後 | おやすみ111回・累計のかけら 32,777・実績67 | おやすみ73回・28,634・実績62 | — |

- シミュレーターを速くした：終盤はあくびが桁違いに多く、ボットが生産者を1体ずつ何千回も買って遅かった

## 分かっている課題（次に見直すこと）

1. **おやすみラッシュ（Phase 6a で軽減）**：受動ボーナスを √ にして、1分以内の周回の連続は 6回 → 3回 に減った。
   残りはオートおやすみ（6c）で連打の手間だけ減らす。
2. **1周目では「昼下がりの各駅停車」より先の生産者を買えない**：後半の生産者は2周目以降の楽しみになっている。
   2周目以降の生産者の到達時刻もシミュレーターで出せるようにする。
3. **オフライン進行はシミュレーションに入っていない**：寝る前に閉じて朝ひらく遊び方の到達時間は未検証。
4. **チャレンジは能動プレイ・冬眠直後の1回ずつしか測っていない**：ゆったりプレイや、報酬を取った後の順番による差は未検証。
5. **羊を数える（Phase 5）はシミュレーションに入っていない**：期待値は DESIGN.md §10 の見積もり（費用 3分ぶん ≒ 上手なときの増え方）だけ。
   自動化が進むとクリックの比重が下がり、マイナス寄りになる見込み。
